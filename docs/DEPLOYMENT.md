# Развёртывание

## WSGI-сервер

Выполняйте из корня проекта после установки build-зависимостей, загрузки локальной
конфигурации и добавления собственной модели и CSV по инструкции README:

```sh
.venv/bin/python -m pip install -r requirements/production.txt
./scripts/serve.sh
```

Gunicorn слушает `127.0.0.1:8000`, использует два синхронных worker-процесса и timeout 120 секунд. Каждый процесс имеет собственную модель в памяти. Количество процессов подбирайте по CPU, памяти и нагрузочным измерениям. Логи выводятся в stdout/stderr. Примеры с фотографиями по умолчанию выключены при запуске через `scripts/serve.sh`.

Использование WSGI-сервера следует [официальной документации Flask](https://flask.palletsprojects.com/en/stable/deploying/gunicorn/). `start.command` предназначен для локальной разработки.

## Конфигурация

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| MODEL_PATH | models/retrained.pkl | Файл активной модели |
| ROSTER_PATH | data/metadata/students_dataset.csv | CSV с колонками ID;Name |
| DATA_DIR | data/raw | Каталог с фотографиями в students/ |
| ENABLE_SAMPLES | 1 локально, 0 через serve.sh | Выдача фотографий примеров |
| PORT | 8000 | Порт локального сервера |
| BIND | 127.0.0.1:8000 | Адрес Gunicorn |
| WEB_CONCURRENCY | 2 | Число процессов Gunicorn |
| DISPLAY_NAME | Instructor | Подпись интерфейса, не учётная запись |
| FACE_MATCH_THRESHOLD | 0.45 | Максимальное расстояние для совпадения |
| FACE_MATCH_MARGIN | 0.05 | Минимальный отрыв от другого студента |

Относительные MODEL_PATH, ROSTER_PATH и DATA_DIR вычисляются от корня проекта. `.env.example` — шаблон; приложение не загружает `.env` автоматически. Передавайте переменные через `export`, менеджер процессов или настройки хостинга.

## Состав поставки

Нужны `backend/`, `frontend/`, доверенная модель в `models/`, CSV из `data/metadata/` (или по ROSTER_PATH), `requirements/`, `deploy/` и `scripts/serve.sh`. Модель, CSV и фотографии исключены из Git: передавайте их отдельно разрешённым способом. Создавайте `.venv` на целевом сервере. При `ENABLE_SAMPLES=0` исходные фотографии не нужны. Путь к модели можно указывать вне папки проекта.

`GET /healthz` проверяет, что процесс отвечает; модель проверяется при старте. Это не полная проверка качества распознавания. Для проверки интеграции используйте тесты из README.

## Перед публичным запуском

Текущий API не имеет авторизации, а `/api/status` при включённых примерах раскрывает имена из датасета. До внешнего доступа реализуйте вход и контроль доступа к распознаванию и данным, постоянное хранение посещений и правила их изменения. Настройте HTTPS/reverse proxy (камера браузера требует защищённого контекста вне localhost), лимиты запросов, менеджер процессов, резервирование модели и мониторинг. Проверьте распознавание на независимой выборке и работу при целевой нагрузке.

GitHub Actions выполняет проверки на синтетических данных без секретов. Он не развёртывает
приложение. GitHub Pages не подходит для Flask backend. Авторизация, БД и reverse proxy не реализованы.
