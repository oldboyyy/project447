# Архитектура

```text
Браузер
  ├── GET /, /attendance, /static/* → frontend/
  └── POST /upload → backend/routes.py
                         └── services/recognition.py → models/retrained.pkl
  GET /api/samples/* → services/samples.py → data/raw/

ml/train.py + фотографии → новый файл models/*.pkl → перезапуск сервера
```

`backend.app.create_app()` создаёт Flask, читает конфигурацию, проверяет модель и регистрирует маршруты. Неверная или отсутствующая модель не позволяет серверу запуститься. `backend/wsgi.py` служит точкой входа для Gunicorn; `python -m backend` запускает локальный сервер.

Frontend состоит из HTML-шаблонов, CSS и JavaScript без npm. URL интерфейса и API сохранены. Файлы выбираются по абсолютным путям от корня проекта; запуск не зависит от текущей рабочей папки при корректном импорте Python-пакета. Страница SDU является локальной копией: её меню, кроме Home и Take Attendance, ведёт на внешний портал.

## Компоненты

| Папка | Назначение | Нужна для обслуживания запросов |
|---|---|---|
| frontend | Страницы, стили, скрипты, изображения | Да |
| backend | API, загрузка модели, распознавание | Да |
| models | Сериализованные имена и 128-мерные векторы лиц | Да |
| data/raw | Фото для обучения и демонстрации | Только при включённых примерах |
| data/metadata | CSV с ID и именами студентов | Да (либо внешний ROSTER_PATH) |
| ml | Команда обучения | Нет |
| docs | Документация | Нет |

## API

| Метод и путь | Результат |
|---|---|
| GET /, /index.php | Главная страница |
| GET /attendance | Интерфейс распознавания |
| GET /static/* | Ресурсы frontend |
| GET /healthz | Состояние процесса: `{"status":"ok"}` |
| GET /api/status | Число людей, тип модели, порог, список примеров |
| GET /api/samples/:id | Фото примера; 404 для отсутствующего/выключенного примера |
| POST /upload | multipart-поле `photo`; результаты, лица, обработанное JPEG в base64 |

Ограничения: 12 МБ на запрос, 30 мегапикселей на изображение; до обработки фото уменьшается до 1600 × 1600. Ошибки ввода возвращают 400, превышение размера запроса — 413.

## Распознавание и хранение

HOG находит лица, dlib строит 128-мерные векторы. По умолчанию совпадение принимается при расстоянии ≤ 0.45 и разнице с ближайшим другим студентом ≥ 0.05. Пороги задаются через FACE_MATCH_THRESHOLD и FACE_MATCH_MARGIN. Расстояние не является процентом уверенности. Неизвестные лица остаются неподтверждёнными; отсутствие совпадения не доказывает отсутствие человека.

Модель кешируется в памяти процесса. Файлы pickle загружаются ограниченным десериализатором; используйте только доверенные модели. Обучение записывает временный файл и затем заменяет целевой; одновременно обучать в один выходной файл не следует.

При запуске `services/roster.py` читает CSV `ID;Name` из `ROSTER_PATH`. API дополняет строки attendance полем `id`, связывая имена модели и CSV. Экспорт содержит колонки ID, Name, Status.

Загружаемые фото и результаты хранятся в памяти, CSV формируется в браузере. Постоянного журнала, базы данных, пользователей и ролей нет. Фотографии примеров являются обучающими данными и не дают независимой оценки точности.
