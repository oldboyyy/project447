# Automatic Attendance System

[English version](README.md)

Учебное локальное приложение для учёта присутствия по распознаванию лиц. Flask обслуживает
страницу SDU и панель посещаемости. Можно загрузить фото, сделать снимок с камеры или включить
распознавание каждые три секунды, проверить результат и скачать CSV.

**Фотографий студентов, их имён, идентификаторов и биометрической модели в репозитории нет.**
Для работы приложения нужны собственные разрешённые данные. Публичные тесты работают без них.

## Возможности и ограничения

- Загрузка фото, захват одного кадра и режим live camera.
- Разметка лиц и явное указание неподтверждённой личности.
- Настраиваемые порог расстояния и отрыв от следующего кандидата.
- Сопоставление имён с ID из CSV, экспорт `ID,Name,Status` в браузере.
- Отдельная команда обучения и запуск через Flask или Gunicorn.

Результаты относятся только к последнему кадру. Авторизации, базы данных и постоянного журнала
нет. «Not detected» не доказывает отсутствие студента. Фото обрабатываются в памяти.
Примеры на обучающих фото не являются независимой оценкой точности.

## Стек и структура

Python 3.11, Flask, dlib / face-recognition, NumPy, Pillow, Gunicorn; HTML/CSS/JavaScript без npm
и сборщика. Проверки: `unittest`, Ruff и Node.js для выполнения настоящего CSV-экспортера.

```text
backend/                Сервер, конфигурация и распознавание
frontend/               Шаблоны, JavaScript, стили и имеющиеся ресурсы SDU
ml/train.py             Обучение на собственных фотографиях
data/raw/students/      Личные фото; в Git только .gitkeep
data/metadata/          CSV со списком студентов; в Git только .gitkeep
models/                 Личная модель; в Git только .gitkeep
tests/                  Синтетические тесты и отдельные локальные проверки реальных данных
requirements/           Зафиксированные зависимости
scripts/, deploy/       Запуск и конфигурация Gunicorn
docs/                   Архитектура, API и развёртывание
.github/                CI и шаблоны для совместной работы
```

## Требования и установка

Нужны Python **3.11**, macOS или Linux, компилятор C++ и CMake для сборки dlib, если готового
wheel нет. На macOS установите Xcode Command Line Tools, на Debian/Ubuntu — `build-essential`.
CMake устанавливается из `requirements/build.txt`. Для всех тестов нужен Node.js **22**;
без него пропускается проверка CSV. Серверу Node.js не требуется.

После создания репозитория войдите в GitHub CLI под аккаунтом владельца.
Команда `gh repo clone project447` выбирает репозиторий этого аккаунта. Для чужого аккаунта
используйте настоящее значение `владелец/project447` со страницы GitHub.

```sh
gh repo clone project447
cd project447
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements/build.txt
python -m pip install -r requirements/development.txt
cp .env.example .env
```

Development-зависимости включают сервер и Ruff. Для обычного локального запуска достаточно
`requirements.txt`, для Gunicorn — `requirements/production.txt`. Сначала установите build-зависимости
в активированное окружение: dlib должен находить установленный CMake.

Отредактируйте `.env` локально и загрузите его в текущую оболочку:

```sh
set -a
. ./.env
set +a
```

Приложение не читает `.env` автоматически. Значения с пробелами заключайте в кавычки;
загружайте только доверенный файл. `.env` исключён из Git. API-ключи не нужны.
`DISPLAY_NAME` задаёт подпись интерфейса, а не учётную запись пользователя.

## Собственные данные и модель

Публичной ссылки на исходный набор студентов нет. Получите фотографии с разрешением на
использование и список студентов из собственного разрешённого источника.

1. Положите по одному фото с одним лицом в `data/raw/students/`. Поддерживаются JPG, JPEG,
   PNG и WebP. Имя файла без расширения становится именем студента.
2. Создайте `data/metadata/students_dataset.csv` с разделителем `;`. Например, с вымышленными данными:

   ```csv
   ID;Name
   DEMO-001;Student One
   DEMO-002;Student Two
   ```

   Файлы для этого примера называются `Student One.jpg` и `Student Two.jpg`. Имена и ID должны
   быть непустыми и уникальными. Программа приводит имена к регистру Python `title()`.
3. Обучите модель в активированном окружении:

   ```sh
   python -m ml.train data/raw/students --output models/retrained.pkl
   ```

   Фото без лица или с несколькими лицами пропускаются. Если пригодных фото нет, существующая
   модель не заменяется. Команда выводит имена файлов — сохраняйте эти логи локально.
4. Имена в модели и CSV должны совпадать полностью. При несовпадении или отсутствии файлов
   сервер не запускается. После смены модели перезапустите приложение.

Базовые модели dlib устанавливаются пакетом `face-recognition-models`; это не модель с
личностями ваших студентов. Используйте только доверенные файлы моделей. Фотографии, CSV,
эмбеддинги и логи исключены из Git. Не публикуйте их через `git add -f` или Git LFS.

## Запуск и использование

После добавления собственных данных и загрузки `.env`:

```sh
python -m backend
```

Откройте <http://127.0.0.1:8000>, нажмите **Take Attendance**, выберите **Upload photo** или
**Live camera**. После проверки лиц откройте **Attendance** и скачайте CSV до закрытия страницы.
Каждое распознавание заменяет предыдущий результат. Ограничения фото: 12 МиБ и 30 мегапикселей.
Камера требует разрешения браузера и localhost либо HTTPS.

На macOS также работает `./start.command`; другой порт: `PORT=8001 python -m backend`.
Запуск Gunicorn из `.venv`:

```sh
./scripts/serve.sh
```

Сервер слушает только `127.0.0.1:8000` по умолчанию. Для примеров на собственных фото задайте
`ENABLE_SAMPLES=1` и перезапустите сервер. Не включайте их при внешнем доступе.
В примере `.env` и серверном запуске примеры выключены по умолчанию; явное значение переменной
имеет приоритет. Это локальный запуск, а не публикация сайта. GitHub Pages не запускает Python backend.

_Место для скриншота: панель с вымышленными данными. Скриншоты реальных студентов не включены._

## Проверки

Без личных данных, `.env` и секретов GitHub:

```sh
ruff check .
ruff format --check .
node --check frontend/static/app.js
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -v
python -m pip check
```

Тесты создают временные вымышленные списки, случайные векторы и пустые картинки; проверяют
правила сопоставления, обработку изображений, ошибки API, согласованность модели и CSV,
экспорт, запуск настоящего Flask-процесса и конфигурацию Gunicorn. Это не оценка точности модели.
Две проверки на собственных фотографиях включаются отдельно:

```sh
PYTHONDONTWRITEBYTECODE=1 RUN_PRIVATE_DATA_TESTS=1 python -m unittest discover -s tests -v
```

Для них нужны ваша модель, CSV и соответствующие обучающие фото. Вывод при ошибке может содержать
имена — не публикуйте его. GitHub Actions запускает публичные проверки при push и pull request в `main`.
